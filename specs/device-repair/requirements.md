# 设备报修功能需求

## 1. 目标与范围

为实验室设备预约小程序增加设备报修闭环：普通用户发现设备故障后可以选择设备、填写故障描述并上传现场照片；管理员收到站内通知后查看详情、开始处理并填写处理结果；用户能够查看自己提交的报修进度。

本功能复用现有用户身份、设备、云存储和站内消息能力，不在用户提交时自动停用设备或取消预约。

## 2. 角色与状态

- **报修用户**：已审核通过且未被禁用的普通用户或管理员。
- **处理管理员**：已审核通过且角色为 `ADMIN` 的用户。
- **报修状态**：`PENDING`（待处理）、`PROCESSING`（处理中）、`RESOLVED`（已完成）。

## 3. 用户故事与验收标准

### R1 报修入口与设备选择

作为设备使用者，我希望从设备详情快速发起报修，避免重复填写设备信息。

- 当用户在设备详情点击“设备报修”时，系统应打开报修页面并自动带入当前设备。
- 当用户从其他入口进入报修页面时，系统应要求从现有设备列表中选择设备，不允许自由输入不存在的设备名称。
- 当设备已被删除或用户未通过审核时，系统应阻止提交并给出明确提示。

### R2 故障信息与照片

作为报修用户，我希望通过文字和照片说明故障，方便管理员判断问题。

- 当用户填写报修单时，系统应要求选择设备并填写 10–500 字的故障描述。
- 用户应能上传 1–3 张现场照片，并可在提交前预览或删除。
- 系统应仅接受微信小程序可读取的图片文件，并在上传失败时保留已填写内容、提示失败原因。
- 当用户没有至少上传 1 张照片时，系统应阻止提交并提示补充故障照片。

### R3 提交与数据一致性

作为报修用户，我希望提交后得到明确结果，避免重复报修。

- 当表单校验通过且照片上传完成时，系统应创建一条状态为 `PENDING` 的报修记录。
- 报修记录应保存设备快照、报修人、故障描述、照片文件 ID、提交时间和更新时间。
- 当服务端创建报修记录失败时，系统不得显示提交成功。
- 当提交成功时，系统应展示成功提示并进入该报修详情或记录列表。

### R4 管理员通知

作为管理员，我希望及时看到新的设备报修，以便安排处理。

- 当报修记录创建成功时，系统应向所有已通过且未禁用的管理员生成站内通知。
- 通知应包含设备名称、报修人、提交时间和故障摘要，并能安全跳转到管理员报修详情。
- 同一报修记录不得因接口重试生成重复管理员通知。
- 微信订阅消息不作为本期强制交付，后续可在配置真实模板后扩展。

### R5 管理员报修列表与详情

作为管理员，我希望集中查看报修记录及照片，以判断处理优先级。

- 管理端应新增“设备报修”入口，并显示待处理数量。
- 管理员应能按 `全部 / 待处理 / 处理中 / 已完成` 筛选报修记录。
- 列表应展示设备、报修人、提交时间、状态和故障摘要。
- 当管理员打开详情时，系统应展示完整描述、全部照片、设备信息、报修人信息和状态时间线。

### R6 管理员处理流程

作为管理员，我希望记录处理过程和结果，使报修形成闭环。

- 当报修状态为 `PENDING` 时，管理员应能执行“开始处理”，系统记录处理人和开始时间。
- 当报修状态为 `PROCESSING` 时，管理员应能填写 2–500 字处理结果并执行“完成处理”。
- 当完成处理时，系统应记录处理结果、完成人和完成时间，并将状态更新为 `RESOLVED`。
- 系统应阻止不符合状态顺序的重复或越级操作。
- 管理员可另行进入现有设备管理或禁用时段功能处理设备停用；报修状态变更本身不自动改变设备状态。

### R7 用户报修记录与结果通知

作为报修用户，我希望查看处理进度和结果。

- 普通用户应能查看仅属于自己的报修记录，并按时间倒序展示。
- 用户应能查看设备、描述、照片、当前状态、提交时间和处理结果。
- 当管理员开始处理或完成处理时，系统应向报修用户生成站内通知。
- 用户不得读取其他用户的报修记录或处理信息。

### R8 图片与访问安全

- 报修图片应存储在 CloudBase 云存储的独立目录中，数据库仅保存云文件 ID。
- 图片文件名不得使用用户输入直接拼接，避免路径注入和重名覆盖。
- 报修集合应使用 `ADMINONLY`，所有业务读写通过云函数完成。
- 云函数应使用 `cloud.getWXContext().OPENID` 识别调用者，不接受客户端传入的用户身份。
- 服务端返回报修数据前应执行本人或管理员权限校验。

## 4. 非目标

- 本期不自动将被报修设备切换为维护状态。
- 本期不自动取消该设备的既有预约。
- 本期不实现维修人员排班、维修费用、备件库存或工单转派。
- 本期不承诺微信订阅消息送达，站内消息为可靠通知渠道。

## 5. 验收结果

- 用户能够完成“选择设备 → 描述故障 → 上传照片 → 提交”的完整流程。
- 管理员能够收到通知并完成“查看 → 开始处理 → 填写结果 → 完成”的闭环。
- 用户能够查看自己的处理进度并收到状态变更通知。
- 未授权用户无法读取、修改报修记录或访问他人的报修数据。
