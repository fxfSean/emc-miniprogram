# 管理员预约管理需求

## 1. 目标与范围

在现有管理端新增“预约管理”，为管理员提供预约总览、预约干预、设备不可用时段管理和预约规则配置能力。

本期包含：

- 日历与列表两种预约总览方式
- 按设备、日期筛选预约
- 查看预约详情
- 管理员取消预约
- 管理员为已通过审核的用户代预约
- 新增、查看和删除设备禁用/维护时段；删除禁用时段即恢复开放
- 配置每日最大预约时长、最多有效预约数、提前预约天数、取消截止时间
- 预约页面须知与后端校验同步使用管理员配置

本期不包含：

- 审批每一笔预约
- 消息订阅或短信通知
- 周期性预约与周期性维护规则
- 导出 Excel 或统计报表

## 2. 角色与术语

- 管理员：`role = ADMIN` 且 `status = APPROVED` 的用户。
- 有效预约：状态为 `BOOKED` 且结束时间晚于当前时间的预约。
- 使用中：状态为 `BOOKED`，且当前时间位于预约开始和结束时间之间。
- 禁用时段：`device_blocks` 中记录的维护、假期或其他不可预约时间区间。
- 恢复开放：删除对应禁用时段；不额外创建“开放时段”记录。

## 3. 用户故事与验收标准

### R1 预约管理入口

作为管理员，我希望从管理首页进入预约管理，以集中处理预约事务。

- 当管理员打开管理首页时，系统应显示“预约管理”入口及功能说明。
- 当非管理员调用预约管理接口时，系统应拒绝访问且不返回预约或用户隐私数据。

### R2 预约总览

作为管理员，我希望用日历或列表查看全部设备的预约，以快速了解占用情况。

- 当管理员进入预约管理时，系统应默认展示当前日期的预约列表。
- 当管理员切换至日历视图时，系统应按月展示每日预约数量，并在选择日期后展示该日预约。
- 当管理员切换至列表视图时，系统应按开始时间展示符合筛选条件的预约。
- 当预约状态随时间变化时，系统应展示“待使用、使用中、已结束、已取消”中的对应状态。
- 当结果为空时，系统应显示明确的空状态。

### R3 筛选

作为管理员，我希望按设备和日期筛选，以快速定位预约。

- 当管理员选择设备时，系统应只展示该设备的预约；选择“全部设备”时应恢复全部设备。
- 当管理员选择日期或日期范围时，系统应只展示与该时间范围相交的预约。
- 当管理员重置筛选时，系统应恢复默认筛选状态。

### R4 预约详情

作为管理员，我希望查看预约详情，以了解预约人、设备、时段和事由。

- 当管理员点击预约记录时，系统应展示预约人姓名、学号、设备名称与编号、预约日期、开始与结束时间、预约事由、状态和创建时间。
- 当关联设备或用户已不存在时，系统应以“已移除”占位，且详情页不得崩溃。

### R5 管理员取消预约

作为管理员，我希望在设备故障等特殊情况下取消预约。

- 当管理员取消待使用或使用中的预约时，系统应要求二次确认并填写取消原因。
- 当管理员确认取消时，系统应将预约改为 `CANCELLED`，记录管理员、取消时间、取消原因和取消来源。
- 管理员取消不受普通用户取消截止时间限制。
- 当预约已经结束或已取消时，系统应禁止重复取消。

### R6 管理员代预约

作为管理员，我希望为已通过审核且未禁用的用户代预约。

- 当管理员发起代预约时，系统应允许搜索并选择已通过审核的普通用户、设备、日期、连续时段和预约事由。
- 当管理员提交代预约时，系统应校验设备状态、过去时间、预约冲突、禁用时段以及目标用户的预约规则限制。
- 当代预约成功时，预约应归属于目标用户，并记录代预约管理员和代预约来源。
- 当并发提交产生冲突时，系统应只允许一笔预约成功。

### R7 设备禁用/维护时段

作为管理员，我希望设置设备不可预约的时间区间，并在需要时恢复开放。

- 当管理员新增禁用时段时，系统应要求选择设备、开始时间、结束时间和原因。
- 当禁用区间与该设备现有有效预约重叠时，系统应阻止保存并提示先处理冲突预约。
- 当禁用区间与现有禁用时段重叠时，系统应阻止重复创建。
- 当管理员删除禁用时段时，系统应二次确认；删除成功后该时间区间应恢复为可预约状态。
- 当普通用户查看预约页面时，禁用时段应继续显示为不可选择。

### R8 预约规则配置

作为管理员，我希望配置预约规则，以适应实验室管理要求。

- 当管理员打开规则配置时，系统应展示当前有效值：每日最大预约时长、最多同时持有预约数、可提前预约天数、取消截止时间。
- 当管理员保存规则时，系统应校验所有值均为合理的正整数或允许为零的分钟值，并拒绝非法输入。
- 当规则保存成功后，新建预约与普通用户取消预约应立即使用新规则。
- 当普通用户进入预约页面时，系统应根据当前配置动态展示预约须知，不得继续显示硬编码数值。

## 4. 默认业务约定

- 管理员可取消“待使用”和“使用中”预约，但不可把已结束预约改为已取消。
- 管理员代预约默认遵守目标用户的全部规则限制，不提供超额绕过。
- 禁用时段通过新增 `device_blocks` 记录实现；恢复开放通过删除记录实现。
- 日期和时间统一按 Asia/Shanghai（UTC+8）解释和展示。
- 管理端接口只返回页面实际需要的用户字段，不返回 `openid`。

## 5. 数据兼容要求

- 继续使用现有 `reservations`、`device_blocks` 和 `settings/reservation` 数据。
- 现有普通用户预约记录无需迁移；新增审计字段为可选字段。
- 规则缺失时继续使用安全默认值：每日 240 分钟、最多 3 个有效预约、提前 7 天、提前 30 分钟截止取消。
